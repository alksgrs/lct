# Что изменено относительно архива ЛЦК_2_0-2

## Расчёт

- Справочник норм `regulations.yaml` вместо `sp42.yaml`: три вида правил — отступ, «не нормируется», запретная зона. У каждого правила акт, пункт, кто и когда сверил. Неподтверждённые правила не загружаются.
- Охранные зоны ВЛ по ПП № 160 с классом напряжения из имени слоя.
- Блоки бордюров и покрытий разбиваются на геометрию, а не берутся точкой вставки: на «Генплане» это скрывало нарушение 1,92 м при норме 2 м.
- `ГАЗОН` больше не распознаётся как газопровод; `ССЫЛКА_КЛ` и другие выноски — оформление, а не кабель; слои только с текстом — оформление.
- Граница: слой границы → оболочка без выбросов → полоса 20 м для протяжённых чертежей. Защита от зависания на огромной области.
- Пространственный индекс вместо перебора: «Генплан» считается за ~20 с вместо зависания.
- Кустарники не ставятся ближе 2 м к деревьям; почвопокровные убраны до появления нормы.
- Расчёт парсит DXF один раз на оба вида посадок.

## API

- Результат: нормы с фактическим ближайшим расстоянием и числом отказов, отказы с нормой и нехваткой, слои с типом и способом распознавания, граница с геометрией.
- `POST /runs/{id}/check` — проверка точки по всем нормам с координатами ближайших объектов.
- `POST /runs/{id}/layers` — ручное назначение типов слоям и слоя границы с пересчётом.
- Правки: перенос, добавление, удаление; проверка отступов между посадками через индекс.
- `GET /runs/{id}/report` — обоснование по каждой посадке.

## Интерфейс

Переписан: план на Canvas с размерными линиями до ближайших объектов, вкладки «Нормы», «Точка», «Отказы», «Слои», 3D на инстансах, тёмная тема, телефон.

## Сборка

`requirements.txt` с FastAPI и uvicorn, Dockerfile для API и для интерфейса, `docker-compose.yml`. Тесты: 39 старых восстановлены и обновлены, добавлены тесты норм, слоёв, API и прогон трёх подоснов с независимой проверкой — всего 125 (на ночь 19 октября).

## Добавлено 19 октября

- ИИ‑визуализация: `greenplan/visual.py`, эндпоинты `GET /visualize/status` и `POST /runs/{id}/visualize`, панель `VisualPanel.tsx` в режиме 3D. Провайдеры Kandinsky (Fusion Brain) и YandexART, ключи из `.env` (образец `.env.example`), без ключа панель говорит, что задать. Тесты `tests/test_visual.py` с подменой HTTP.
- Нормы: строки «край тротуара», «опора освещения — кустарник» сверены с текстом таблицы 3.6.1; добавлены «ось трамвайных путей» (5 / 3 м), «подпорная стенка» (3 / 1 м), «подошва откоса» (1 / 0,5 м), тип объекта SLOPE. У каждого правила `source_url`. В примечания добавлены широкие кроны у жилых домов (10 м) и СИП (5 м).
- Слои: блоки на нераспознанных слоях типизируются по имени блока; слои типов покрытий из ведомости (`ТИП_1`, `ГП_2…`) — проезд или тротуар. На Харьковской раньше 304 посадки (19 деревьев, 285 кустарников) стояли прямо на покрытии с нераспознанных слоёв — теперь таких нет. Тесты `tests/test_parser_content.py`.
- DXF с посадками собирается при первом скачивании: на Харьковской расчёт стал быстрее на ~18 секунд.
- Сборка проверена без Docker Hub: чистый Python 3.12 по `requirements.txt`, полный набор тестов на свежих версиях библиотек, фронт с `VITE_API_URL=/api` за nginx с конфигом проекта, сквозной прогон трёх подоснов через прокси, `docker compose config`.
- `docs/ЗАЩИТА.md` — шпаргалка к защите, `docs/screenshots/` — экраны для презентации, `docs/demo.webm` — запасное видео демо.

## Добавлено 19 октября, вечер: травянистые покрытия и элементы скверов (п. 3 ТЗ)

- `greenplan/planner/greening.py` — газоны, живые изгороди, цветники. Настройки — раздел `greening` в `data/rules/planting.yaml`.
- Газоны: участок минус покрытия, здания, МАФ с проектными отступами; слой `PLANTING_LAWN`, штриховка GRASS.
- Живые изгороди: вдоль тротуаров и проездов, проверены по всем нормам для кустарников и по охранным зонам ВЛ; слой `PLANTING_HEDGES`. Кустарники под изгородью убираются.
- Цветники: в глубине крупных газонов, только там, где можно сажать кустарник, и не ближе 1 м от любых сетей; слой `PLANTING_FLOWERBEDS`.
- В API: `greening` в результате и отчёте, в сводке `lawn_m2`, `hedges_m`, `flowerbeds`. Интерфейс: газоны, изгороди, цветники на плане и в 3D, переключатели в легенде, раздел на вкладке «Нормы».
- Тесты: `tests/test_greening.py`, в `test_samples.py` изгороди и цветники проверяются по нормам на трёх подосновах.

## Добавлено 19 октября, ночь: ИИ‑визуализация без Fusion Brain

- Новые генераторы: GigaChat (Сбер, внутри рисует тот же Kandinsky) и Pollinations (FLUX, работает без ключа). Генераторы опрашиваются по очереди: YandexART → GigaChat → Fusion Brain → Pollinations; если один отказал, рисует следующий, в панели видно, кто не сработал и почему.
- YandexART: кроме API‑ключа принимается OAuth‑токен аккаунта Яндекса (сам обменивается на IAM‑токен) и готовый IAM‑токен, добавлен заголовок `x-folder-id`. Ошибки объясняются по‑русски: 401 — какой ключ нужен, 403 — роль `ai.imageGeneration.user`, каталог и платёжный аккаунт; если вместо секрета вставлен идентификатор ключа `aje…`, это сказано прямо.
- GigaChat: токен по «Ключу авторизации», кэш на 30 минут, новый адрес `api.giga.chat` и запасной `gigachat.devices.sberbank.ru`, подсказка про сертификат Минцифры.
- `python -m greenplan.visual` — проверка ключей без интерфейса: каждый настроенный генератор рисует тестовый участок, причина отказа печатается.
- В панели выбор генератора, список не сработавших с причинами. `POST /runs/{id}/visualize` принимает `provider`, отвечает `provider_name` и `skipped`.
- Тесты `tests/test_visual.py`: 25 сценариев с подменой HTTP, включая цепочку отказов, обмен OAuth‑токена, ошибку сертификата, ограничение частоты Pollinations.

## Нужно от команды

- Арина: проверить строки с пустым `verified_by` в `regulations.yaml` (тротуар, опора освещения — кустарник, трамвай, подпорная стенка, откос) по ссылке `source_url` и поставить подпись.
- Получить ключ YandexART или GigaChat (README, раздел «ИИ‑визуализация»), положить в `.env` и проверить командой `python -m greenplan.visual` до питча. Без ключей рисует Pollinations, но с ограничением частоты.
- Запустить `docker compose up --build` на своей машине.
